<h1 align="center">
使用 <em>AReaL</em> 构建 Pacman 游戏智能体
</h1>

<p align="center"><em>从视觉语言模型到长程游戏智能体</em></p>

本文探讨一个实际问题：如何训练视觉语言模型（VLM），使其不再只回答单个静态提示，而是成为能够在整局游戏中连贯行动的交互式智能体？我们以 Pacman
为例研究这一问题。[MaaPacman](https://codehub-dg-g.huawei.com/AgenticRLGaming/MaaPacman)
提供可控的游戏环境与交互适配器，AReaL 则提供 rollout 和分布式强化学习基础设施。

模型反复观察游戏，从当前状态的可行动作集合中选择动作，并从贯穿完整游戏轨迹逐步显现的后果中学习。我们的目标不只是最大化 Pacman
分数，更是理解可靠训练长程视觉智能体所需的任务定义、反馈设计和系统支持。

## 1. 动机：为什么 Agentic RL 应该走进游戏

[ARC Prize](https://arcprize.org/) 的 ARC-AGI-3
不再采用静态谜题，而是换成规则从不预先说明的陌生小游戏：智能体必须通过实际游玩自行学会规则。图 1 已将 Agentic RL 应该走进游戏的理由浓缩在一张图中。人类大约用
170 个动作就能通过七个关卡，而表现最好的 AI
智能体无论耗费多少动作，成绩曲线始终贴近图底。它们缺少的不是知识，也不是单次推理能力，而是在一个会对其行动作出回应的世界中持续采取连贯行动的能力。

![ARC-AGI-3 中人类与 AI 的差距](../assets/figures/arcagi3_human_ai_gap.png)

*图 1。ARC-AGI-3 上已通关的关卡数与所用总动作数。黄色表示人类玩家，绿色表示表现最佳的 AI
智能体。图片来源：[ARC Prize](https://arcprize.org/)。*

正是这一差距推动了整个领域的转向。各实验室不再只是扩展静态数据集，而是开始在类游戏世界中训练智能体。小红书（Rednote）dots studio 的
[dots3-note Preview](https://studio.dots.ai/dots/dots3-en.html) 是 dots3
系列首个开放权重模型。它在数千个全新的交互环境中接受强化学习训练，从而能够探索、更新记忆，并在任务进行中调整策略；同时以 100 分中的 6.9 分领跑官方 ARC-AGI-3
harness（图 2）。基准测试、模型发布和训练方案正汇聚到同一种问题形态：一个智能体、一个会作出反应的环境，以及一项要经过许多步才会到来的奖励。

![dots3-note Preview 报告的 ARC-AGI 得分](../assets/figures/dots3_arcagi_scores.png)

*图 2。即使是领先模型，在官方 ARC-AGI-3 harness 上也只有 6.9 分；Claude Opus 4.8 为 1.5 分，GPT-5.5 为 0.4
分。图中各行摘自 dots studio 发布的评估表；`*` 表示其内部运行结果，`-` 表示未报告。*

我们认为，现在正是 AReaL 进入这一领域的时候。AReaL 已经提供了大部分基础能力——异步 rollout、PPO/GRPO
和多模态训练——但其参考示例大多将多轮交互与图像条件输入分开演示，而且没有任何示例把实时运行的环境持续纳入闭环。游戏智能体必须同时具备这两种能力，还要处理随状态变化的动作合法性，以及跨越数百步的信用分配。游戏是构建这些能力最可控的场景：规则明确、结果可衡量、回合可重置。本文只是我们朝这个方向迈出的第一步，并非一套已经完成的
Agentic RL 框架；Pacman
是我们刻意选取的小型实例——一张迷宫的渲染成本低，也易于检查，但清空它仍需数百个相互依赖的决策，其中早期一次错误转向就可能决定最终结果。

## 2. 问题定义

如何训练视觉语言模型（VLM），使其通过一系列与环境状态相对应的决策，在长程游戏中完成感知、决策与行动？

与静态视觉语言任务不同，Pacman
需要闭环交互。模型的每次输出都会改变环境，也会决定下一次观察和可行动作集合。一局游戏可能包含数百个相互关联的决策。这些决策共同决定最终结果。

### 2.1 两种策略设置

我们研究两种策略设置。一种是**原始动作策略**，另一种是 **Harness 介导的 option 策略**。二者采用不同的动作抽象。

Stage I 在无幽灵环境中使用原始动作策略。Stage II 在启用幽灵的环境中使用 Harness 介导的 option 策略。这些阶段描述的是能力课程，而不是
Pacman 中带编号的游戏关卡。Stage I 先研究视觉迷宫定位和局部导航。Stage II 再加入动态危险和高层目标。

**全局动作词表** `V` 是一组固定的动作标识符。每个标识符由一个输出 token 表示。在决策 `t` 时，**状态相关的可行动作集合（admissible-action
set）** `A(s_t) ⊆ V` 包含环境或确定性 option Harness 允许的标识符。约束解码将采样限制在 `A(s_t)`
内。**策略支撑集**指应用解码规则后概率非零的动作集合。它不是可行动作集合的另一个名称。

在每种策略设置内，`V` 保持固定。只有 `A(s_t)` 会随决策变化。对于原始动作策略，`V` 包含四个方向标识符。对于 Harness 介导的 option 策略，`V`
是一个固定且有界的高层 option 标识符词表。两种情况下，约束解码都将采样限制在当前的 `A(s_t)` 中，而不是完整词表。

| 设置                           | 模型输出                              | 单次决策的可行动作集合               | 执行单元                         | 本研究阶段          |
| ------------------------------ | ------------------------------------- | ------------------------------------ | -------------------------------- | ------------------- |
| **原始动作策略**               | 一个原始动作标识符                    | 当前状态下开放方向对应的标识符       | 一个原始环境步                   | Stage I · 无幽灵    |
| **Harness 介导的 option 策略** | 一个 Harness 生成的高层 option 标识符 | 当前状态下所提供 option 对应的标识符 | 一段有界且逐步重新验证的原始动作 | Stage II · 启用幽灵 |

使用原始动作策略时，模型的一次决策控制一个游戏步。约束解码会移除当前状态下被阻挡的方向。模型仍负责选择下一个低层动作。

使用 Harness 介导的 option 策略时，确定性 option Harness 会创建一小组高层 option。这些 option
来自三个预定义的策略族：收集豆子、规避危险或追逐可食用幽灵。只有策略族是预定义的。Harness 会根据当前游戏状态重新计算每个 option
的目标、路线和可用性。我们将每个由此得到的选择称为 **Harness 生成的高层 option**。只有当前所提供 option 的标识符会进入 `A(s_t)`。

模型选择一个所提供的 option 后，Harness 会执行对应的原始动作。每执行一步，Harness 都会检查该 option
是否完成或失效。这就形成了时间动作抽象。模型选择的是 Pacman 接下来要追求的高层目标，而不是下一个移动方向。低层路线构建和安全验证仍由确定性 Harness 完成。

在两种设置下，任务都要求：

1. **视觉定位：** 从当前游戏画面中提取与任务相关的信息。
1. **闭环决策：** 根据先前动作所产生的状态调整每次决策。
1. **状态相关的动作可行性：** 只选择 `A(s_t)` 中的标识符。对于 Harness 介导的 option 策略，该可行动作集合以及每个所提供 option
   对应的具体目标都可能在两次决策之间发生变化。
1. **长程决策：** 考虑可能在很多次决策之后才显现的后果。
1. **泛化：** 将学到的策略迁移到未见过的游戏状态和迷宫布局，而不是记住一条轨迹。

## 3. 挑战

### 3.1 缺少基本感知与规划时，仅靠稀疏奖励无法启动学习

我们先测试基础 VLM 能否从像素中恢复游戏状态。在三个真实演示帧上，它准确识别 Pacman 行列位置的结果为 `0/3`。完整恢复 `OPEN` 和 `BLOCKED`
方向集合的结果为 `0/3`。生成有效 25×21 ASCII 迷宫的结果也为 `0/3`。它对剩余豆子数量的平均绝对误差为 48。模型能认出画面是
Pacman，却无法恢复控制所需的状态。

这给强化学习带来了冷启动问题。在早期一次针对未训练模型的纯图像测试中，32 个 rollout
无一完成迷宫。每个回合都达到步数上限，并产生相同的负回合回报。组内回报没有差异，因此组相对归一化会为每个样本赋予零优势，也就无法提供策略梯度信号。增加 rollout
长度无法修复缺失的视觉定位或规划能力。它可能只会产生同样缺乏学习信号、但更长且成本更高的轨迹。

下面的 seed-0 重放展示了这种失败。原始、未经训练的 Qwen3.5-9B 策略几乎没有取得有效进展。该回合最终以 `STUCK`
终止。这一行为反映了视觉定位与规划能力的不足。

这一冷启动障碍促使我们采用课程式训练。我们分阶段引入视觉定位、局部动作选择和更长程的规划。这样，初始策略可以先学会这些能力，再尝试完成整局游戏。

### 3.2 反馈周期长，GPU 显存需求高

一次训练包含 49 次优化器更新，每次更新使用 48 个 rollout 回合。从 Iter1 的第一个 rollout 到 Iter49 的最后一个
rollout，整次训练共耗时 46.21 小时。这个时间包括各批 rollout 之间的优化器更新。

架构或实验设计中的细微错误可能要过数小时才会出现在学习曲线上。到那时，训练可能已经消耗了大量算力。

这些实验还需要大量 GPU 显存。vLLM rollout 引擎、FSDP actor 和可选的参考模型共享同一台 8-GPU 节点上的计算和显存。较长的 rollout
回合需要更多轨迹存储，也会增加对数概率计算成本。因此，模型卸载、显存感知分批、分布式轨迹处理和检查点保留都是训练设计中必需的部分。

### 3.3 Rollout 与训练必须使用相同的已记录动作掩码和温度

约束解码把每个采样输出限制在当前状态相关的可行动作集合内。即使所有实际执行的动作都可行，rollout 仍可能产生错误的 PPO 更新。当 rollout
与训练使用不同的可行动作集合或温度为所选动作计算概率时，就会出现这个问题。

PPO 可能把这种概率计算差异误认为策略变化。有效样本可能因此被裁剪或拒绝，训练也可能把梯度传入不可行动作的
logits。即使所有实际执行的动作都可行且损失为有限值，这些问题仍可能发生。第 4.3 节说明我们如何让 rollout 与训练使用一致的概率定义。

### 3.4 反馈时间尺度与回合权重是两个独立选择

长程学习包含两个独立的设计选择。第一个是反馈时间尺度，它决定每次决策收到什么信号。第二个是回合权重，它决定每个回合获得多少总优化权重。

回合级反馈让学习与整局游戏结果对齐，但会把同一个粗粒度任务信号分配给回合中的每次决策。环境步级或 option
级反馈在时间上更精确，但可能遗漏之后才显现的后果。这些反馈时间尺度互为补充，不能相互替代。

回合权重是另一个问题。直接对参与训练的 token
取平均，会因为较长轨迹包含更多模型决策而让它产生更大影响。训练目标应保留预期的反馈时间尺度，同时不能让回合长度决定回合权重。第 4.5 节说明我们如何在目标中处理这两个选择。

## 4. 方法

### 4.1 系统架构：MaaPacman 作为强化学习环境适配器

图 3 从左到右展示了整个流程。MaaPacman 位于强化学习工作流与各个 Pacman 游戏实例之间。它向工作流提供 Gym 风格的 API。`reset(seed)`
启动一个回合。`step(action)` 返回下一帧 RGB 观测、基础奖励、终止和截断标志，以及结构化游戏元数据。`render()`
返回当前帧。每个环境对象管理一个隔离的 `pacman-python` 游戏实例。工作流不需要处理游戏进程的细节。

![MaaPacman–AReaL 运行时架构](../assets/figures/maapacman_areal_architecture.png)

*图 3。每个 MaaPacman 环境对象向强化学习工作流提供 Gym 风格的接口，并将动作发送给一个隔离的 Pacman 游戏实例。rollout
策略负责选择动作。FSDP actor 从成组轨迹中学习，但不直接控制游戏。*

在 rollout 期间，工作流将 RGB 观测和当前可行动作集合发送给策略。对于 option 策略，它还会发送每个可用 option
的元数据。策略返回一个动作标识符。环境或 option Harness 将该标识符映射为原始动作或具体 option。图 3 中的 “legal option support”
表示状态相关的可行动作集合 `A(s_t)`，而不是策略支撑集。执行动作后，环境返回游戏事件和终止状态。`areal-pacman`
工作流应用实验奖励，并将交互记录组成轨迹。AReaL 使用这些轨迹训练，再将更新后的权重发送回 rollout 策略。

四个仓库的分工如下：

| 仓库            | 职责                                                                                                 | 明确边界                                 |
| --------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| `pacman-python` | 具体游戏实例：Pygame 状态转移、RGB 帧、结构化状态和终止事件                                          | 仅负责游戏语义；不提供强化学习接口       |
| `MaaPacman`     | Gym 风格的无头适配器、隔离的游戏 worker，以及确定性的 option Harness                                 | 负责环境交互与规划；不负责分布式强化学习 |
| `areal-pacman`  | 环境到 AReaL 的工作流、提示词、奖励函数、配置、评估和实验记录                                        | 负责实验语义；不实现通用 FSDP/vLLM       |
| `AReaL`         | 异步 rollout、PPO/GRPO、vLLM、FSDP、检查点、分布式数据传输，以及我们在训练侧加入的受约束对数概率扩展 | 不包含游戏环境或 option 生成逻辑         |

这种分工让我们可以分别测试游戏事件、奖励和分布式策略更新，也让控制流程更加清楚。rollout 策略在游戏中执行动作，训练 actor 只负责更新权重。

### 4.2 Harness 介导的 option 策略：让模型选择意图

使用 Harness 介导的 option 策略时，模型选择高层目标，而不是一个移动方向。在每次决策时，确定性 Harness 会创建一组有界且在当前状态下有效的
option。这些 option 来自三个固定的策略族：

- **收集豆子：** 向获准的豆子目标移动；
- **规避危险：** 向安全的逃生锚点移动；
- **追逐可食用幽灵：** 接近处于脆弱状态的幽灵。

每个 option 都包含目标、第一个原始动作、步数上限和安全元数据。VLM 从当前可行动作集合中选择一个 option 标识符，而不是输出固定的动作列表。Harness
使用广度优先搜索（BFS）和手工安全检查，将 option 转换为原始动作。`COLLECT`、`AVOID` 和 `ELIMINATE` 的步数上限分别为
`min(8, d)`、`min(3, d)` 和 `min(6, d)`。这里，`d` 是当前最短路径距离。每执行一个环境步，Harness 都会重新计算并检查策略和目标。当
option 完成、失效、达到步数上限，或回合结束或被截断时，Harness 就会停止。它不会盲目重放固定路线。

在我们的运行中，模型选择的每个 option 平均覆盖 **1.49 个原始环境步**。原始动作策略的每次模型决策只覆盖一个环境步。因此，Harness
减少了模型调用次数。减少幅度不大，因为大多数 `COLLECT` option 都以附近的一颗豆子为目标，并在一步后结束。

Harness 负责检查动作可行性、构建路线和执行安全规则。学习策略负责根据当前视觉状态选择最合适的高层 option。这种设计减少了模型调用，但没有把完整的 Pacman
策略写死在 Harness 中。

### 4.3 Rollout 与训练之间的约束对齐

在决策 `t`，令 `A_t = A(s_t) ⊆ V` 表示所记录的状态相关可行动作集合。约束解码在温度 `T` 下，将 rollout 策略在 `A_t`
上重新归一化。[AReaL 的解耦 PPO 目标](https://arxiv.org/abs/2505.24298)跟踪三个策略。`π_behav` 是 vLLM
rollout 策略，`π_prox` 是更新前的 actor，`π_θ` 是当前 actor。随后，AReaL
应用[裁剪 PPO 更新](https://arxiv.org/abs/1707.06347)。行为校正比率比较 rollout 与训练如何为所记录的动作计算概率：

```math
w_t = \frac{\pi_{\mathrm{prox}}(a_t \mid s_t,A_t;T)}
           {\pi_{\mathrm{behav}}(a_t \mid s_t,A_t;T)}.
```

当 `π_behav` 与 `π_prox` 参数相同，并使用相同的 `A_t` 和 `T` 时，`w_t = 1`。如果 rollout
与训练使用不同的可行动作集合或温度，即使模型参数相同，`w_t`
也可能不等于一。这是归一化错误，而不是策略陈旧性。它会产生错误的重要性权重，可能拒绝或裁剪有效样本，还可能把梯度传入不可行动作的 logits。

[Huang 和 Ontañón](https://arxiv.org/abs/2006.14171)
研究了类似的不一致。他们的智能体从掩码分布中采样动作，却使用未掩码分布计算策略梯度更新。他们将其称为**朴素无效动作掩码（naive invalid action
masking）**。在他们的 PPO 实验中，与一致掩码相比，这种不一致会产生更大的 KL 散度和更不稳定的收敛过程。

rollout 时，工作流将 `A_t` 中的标识符映射为精确的 tokenizer ID。一个小型 AReaL 请求适配器将这些 ID 转发给 vLLM 内置的
`allowed_token_ids`，使其在采样前屏蔽其他 token。rollout 将采样得到的 token、温度、受约束行为对数概率 `log π_behav`
和精确的 `A_t` 保存在同一条记录中。这能让它们在分布式分批过程中保持对齐。

更新前，FSDP actor 重新计算 `log π_prox`。在 PPO 前向传播期间，它计算
`log π_θ`。这些操作计算已记录动作的对数概率，不会生成新动作。二者都在已记录的 `A_t` 上对 actor logits 进行归一化。启用 KL
正则化时，`π_ref` 也使用相同的集合和温度。`π_ref` 不是 PPO
比率的分母。由于参数或版本不同，各策略给出的概率可以不同，但它们必须使用相同的可行动作集合和归一化规则。

只在 rollout 阶段应用动作掩码还不够。每个对数概率都必须使用已记录的可行动作集合和温度。这条规则适用于 rollout 行为策略、近端 actor、当前 actor
和可选的参考策略。

### 4.4 奖励设计：从事件学习，而非原始分数

Stage I 的原始动作策略配置根据环境发出的结构化游戏事件计算奖励，而不是使用游戏的原始分数。在 256 步配置中，第 $t$ 步一个有效且已执行的动作获得：

```math
\begin{aligned}
r_t ={}& n_t^{\text{pellet}}
+ n_t^{\text{power}}
+ 50\,\mathbb{1}[\text{level cleared}] \\
&- 0.05
- 0.5\,\mathbb{1}[\text{wall collision}]
+ r_t^{\text{progress}}.
\end{aligned}
```

水果仍然可见，但没有直接训练奖励。为了提供更密集的反馈，我们根据到最近普通豆子的最短路径距离变化加入进度项：

```math
r_t^{\text{progress}}
= 0.1\,c_t\,(d_{t}^{\text{before}}-d_{t}^{\text{after}}),
\qquad
c_t = 1-\rho_t,
\qquad
\rho_t=\frac{m_t}{m_0}.
```

这里，$m_t$ 是第 $t$ 步之后剩余的普通豆子数量，$m_0$ 是初始数量。如果同一步已经收集了普通豆子，我们就不计算进度项，以免对同一事件重复奖励。系数 $c_t$
使进度奖励在游戏后期只剩少量豆子时最强。无效或无法解析的响应会使该模型决策获得 `-50`，并终止回合。

Stage I-B 沿用了相同的事件奖励和固定步成本。它使用原始逐决策反馈，不做奖励或优势归一化。Stage I-B
仍是无幽灵环境。幽灵、死亡和安全拒绝奖励只出现在启用幽灵的配置中。

这种塑形奖励是训练信号，而非成功判据。严格完成关卡和留出成功率仍是主要评估指标。

### 4.5 从环境奖励到策略目标

奖励函数定义环境提供什么反馈。目标契约定义训练如何分配、归一化和归约这些反馈。我们从三个维度描述目标契约：反馈时间尺度、归一化和回合权重。

**反馈时间尺度。** 一次决策可以接收下一个环境步的奖励。高层 option 也可以接收其承诺执行区间内的奖励总和：

```math
R^{\text{option}}_{e,j}
= \sum_{t\in\text{committed span}(e,j)} r_{e,t}.
```

这两种信号都是时间局部反馈。它们不会为被评分的环境步或 option 之后发生的事件分配信用。option
跨度回报仍是局部回报，不是反事实优势或状态条件优势。对于回合级信号，我们改为对一个 rollout 回合中的所有塑形步奖励求和：

```math
R_e=\sum_t r_{e,t}.
```

这个信号保留了整回合目标。回合中的每次模型决策都会收到同一个粗粒度任务信号。

**归一化。** 局部信号或回合级信号既可以直接使用原始值，也可以进行归一化。在回合级组相对契约中，从同一个初始提示词采样得到的回报使用组内样本标准差进行归一化：

```math
G_e=\frac{R_e-\mu_{\text{prompt}}}
{\sigma_{\text{prompt}}+10^{-5}}.
```

对局部信号做归一化会改变其尺度或比较组，但不会改变反馈时间尺度。回合聚合会保留每项奖励对总和的贡献，但会丢失它出现的时间位置。

**回合权重。** 先在每个 rollout 回合内对损失求平均，再在各回合间求平均：

```math
L=\frac{1}{|E|}\sum_{e\in E}
\left(\frac{1}{N_e}\sum_{t\in e}L_{e,t}\right).
```

这里，$N_e$ 是 rollout 回合 $e$ 中有效且参与训练的动作 token 数量。这能防止较长回合仅因为包含更多训练 token 而获得更大权重。例如，包含 200
次决策的回合和包含 50 次决策的回合都会先在各自回合内平均 token 损失。数据管线保留回合边界和编码后的可行动作集合，同时在各 worker 之间平衡 token 负载。

### 4.6 AReaL 提供了什么，Pacman 又需要什么

[AReaL](https://github.com/inclusionAI/AReaL) 提供异步
rollout、PPO/GRPO、分布式推理与训练、检查点、多轮工作流和多模态支持。它的参考示例将多轮交互和图像输入分开演示。GSM8K
重试循环是纯文本示例。`VisionRLVRWorkflow` 每个回合只进行一次图像条件生成。

MaaPacman 将多轮交互与图像输入结合起来。每次模型决策前，它都会渲染当前游戏状态，并在提示词中加入一张新的 PNG。AReaL 在 rollout 和训练中保留对应的
VLM processor 输出。一个选定的 option 可能在下一次模型调用前执行多个原始环境步。因此，模型每次决策接收一张新图像，而不是每个环境步接收一张。

该集成还会把每个状态的可行动作集合从 rollout 传递到 actor
和参考策略的对数概率计算中。这样，生成和训练使用相同的受约束策略定义。它还会在分布式分批过程中保留回合身份。因此，即使轨迹长度不同，每个回合也能获得相等的损失权重。该集成还支持长回合、变时长
option、VLM 显存管理、检查点保留和可复现实验记录。

这些改动让基于 AReaL 的技术栈可以训练具有状态相关可行动作的 Pacman agent。当前接口仍是 Pacman 专用接口，还不是通用的受约束 agent API。

### 5.1 Stage I：无幽灵的原始动作导航

在两个 Stage I 阶段中，模型都读取当前迷宫图像，并选择一个可行的原始方向。Stage I-B 从 Iter16 开始，并使用更长的 rollout

#### Stage I-A：256 步启动训练与检查点选择

Stage I-A 使用 Qwen3.5-9B 和 256 步 rollout 上限。每个动作都是一个原始方向

#### Stage II 说明了什么

继续训练前，Iter25 已经可以使用启用幽灵的 option 策略，并产生 12/12 条不同的 option

## 6. 经验与启示

### 6.1 最新检查点不一定最好

Iter16 在终局评估中优于 Iter49。Iter49 仍有较高的塑形奖励和 92.2%
的平均豆子清除率。因此，应保留周期性检查点，并使用固定的终局评估套件选择最佳检查点。最新检查点不一定最好。

我们不知道 Iter49 为什么退化。游戏后期状态覆盖有限和回合后段信用不足都是可能原因。这次运行不能证明训练收敛到了局部最优。

### 6.2 奖励处理会改变策略学习的内容

奖励处理方式决定策略学习什么。对局部奖励做归一化，不会把它变成回合级反馈。回合回报让学习与整局游戏结果对齐，但时间信用更粗。按回合平均还能防止较长轨迹仅因为包含更多训练
token 而获得额外权重。

这些运行没有单独比较上述选择。Stage I-A 和 Stage I-B 的初始化与 rollout 时域也不同。Stage II
还改变了环境和动作接口。公平比较需要匹配的消融实验。

### 6.3 代理指标不是任务本身

豆子清除率、塑形奖励、得分和动作多样性有助于解释行为，但不能定义成功。Iter49 的平均豆子清除率为 92.2%，获胜数却是 0/3。评估应先看终局获胜数和失败原因。

### 6.4 安全模式迁移不等于通用 Pacman 游戏能力

44/50 的结果说明策略可以在安全模式下迁移到不同的迷宫布局，但不能说明它具备通用 Pacman 游戏能力。启用幽灵会改变动态、奖励和失败模式。对于 option
策略，它还会改变可用的 option。

### 6.5 只有学习曲线还不够

状态—动作元数据未对齐或 rollout 不完整，都可能表现得像策略失败。应保留轨迹记录，并标明哪些检查点真正完成了训练。没有这些信息，学习曲线很难解释。

## 7. 局限与后续工作

当前实现和证据仍有以下不足：

1. **策略并非只使用像素。** option 策略会收到截图和可用 option 的权威元数据。因此，它测试的是多模态 option
   选择，而不是纯像素控制。下一步应测试双帧输入或地图加局部观测。
1. **50 迷宫结果不包含幽灵。** 在另外的原型运行中，Harness 介导的 option 策略完成过启用幽灵的游戏。本文报告的 50
   迷宫套件关闭了幽灵和水果，以单独测试几何导航。幽灵感知套件应记录死亡、可食用幽灵选择和安全拒绝。
1. **Option Harness 是手工设计的。**
   策略族、目标选择、路线和安全门都是规则，而不是学习到的行为。长期目标是在保留确定性动作可行性和安全检查的同时，共同学习策略与 option 生成器。
1. **评估覆盖仍然有限。** 应使用多个随机种子重复训练，并在相同的 50 个迷宫上评估 Iter16、Iter25 和 Iter31。继续训练前，还应检查 Iter25
   和 Iter31 都失败的六个迷宫。
1. **奖励比较需要匹配的消融实验。** 应固定初始化和预算，再比较原始逐决策反馈、整回合归一化、原始 option
   跨度反馈，以及带有小型有界局部辅助项的回合目标。该辅助项目前只是一个方案。应先使用固定系数，再尝试自适应梯度平衡。

## 8. 结论

Pacman 虽小，却包含视觉智能体强化学习中的关键难点：状态相关动作、长回合、延迟信用、rollout 与训练对齐，以及分布式执行。MaaPacman
提供确定性且可重置的环境。AReaL 提供异步 rollout 和分布式训练。

在安全模式下，训练后的策略解出了 50 个留出迷宫中的 44
个，基础模型一个也没有解出。实验还表明，最新检查点可能比更早的检查点更差。奖励归一化改变的是学习目标，而不只是指标尺度。

下一步，我们将测试受控的幽灵动态，并进行匹配的消融实验。我们会继续明确区分结果能够说明什么，以及不能说明什么。
